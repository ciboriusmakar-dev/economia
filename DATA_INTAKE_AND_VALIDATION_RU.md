# Приём данных и контроль качества ECONOMIA 1.9.5

## 1. Поддерживаемые форматы

`economia_ingest.py` принимает CSV, TSV, XLSX, JSON-stat 2.0 и ZIP с этими форматами.

```bash
python economia_ingest.py путь/к/файлу.csv --out data/intake
python economia_ingest.py путь/к/пакету.zip --out data/intake
python economia_ingest.py папка/с/таблицами --out data/intake
```

Результат: `intake_manifest.json`, исходные файлы из ZIP в `raw/`, нормализованные копии в `processed/`. SHA-256 считается для оригинала и нормализованной копии. Исходный файл не изменяется. Для XLSX используется активный лист и значения ячеек; формулы, требующие пересчёта Excel, не вычисляются программой.

Для XLSX установите зависимости: `pip install -r requirements.txt`.

## 2. Контроль качества

`economia_quality.audit_table` проверяет заголовки, пропуски, числовые значения, полные дубли, дубли заданных ключей, пропущенные годовые/квартальные/месячные периоды. Отсутствующие значения `:`, `..`, `-`, `NA` не превращаются в ноль.

Единицы и классификации не угадываются: если паспорт или метаданные их не задают, выдаётся предупреждение. Подсказки из заголовков не являются доказательством единицы. Проверка допустимости отрицательных значений должна задаваться по конкретному показателю.

`compare_sources` сопоставляет наблюдения по ключам и выявляет различия значений и метаданных (единица, валюта, ценовая база, классификация). Сравнивать можно только семантически сопоставимые данные. Различия источников не усредняются автоматически.

## 3. Независимая сверка

Заполните `INDEPENDENT_REFERENCE_TEMPLATE.csv` независимыми опубликованными значениями. У каждой строки обязательны источник и единица измерения. Сравнение:

```bash
python independent_validation.py model_predictions.csv reference_values.csv --keys entity_id,indicator_id,period,geography_id --value value --abs-tol 0.01 --rel-tol 0.001
```

Метрики: MAE, RMSE, MAPE (только для ненулевого эталона), максимальная абсолютная ошибка. Пропущенные эталонные ключи ведут к FAIL; отсутствие эталонного набора — NOT_TESTABLE. Допуски должны быть определены заранее с учётом округления и методологии публикации.

## 4. Протокол M01–M14

Полная матрица входов, контрольных расчётов, метрик и PASS/FAIL — `EMPIRICAL_TEST_PLAN_M01_M14_RU.csv`. Текущие блокировки по каждому модулю — `EMPIRICAL_STATUS_M01_M14_RU.csv`.

PASS присваивается только после прохождения заранее установленного критерия на реальных сопоставимых данных. Синтетические тесты подтверждают программное поведение, но не точность экономической модели. PARTIAL_PILOT не равен PASS.

## 5. Ограничения

- Автоматическое определение единиц только по заголовку ненадёжно; требуется паспорт источника.
- Частотность периода может быть не распознана для нестандартных форматов.
- Структурный импорт не доказывает корректность классификаций, дефляторов, сезонной корректировки или экономического смысла.
- XLSX формулы читаются как сохранённые значения; если Excel не сохранил рассчитанное значение, оно может быть пустым.
- ZIP защищён от path traversal и ограничен по размеру распаковки; зашифрованные архивы не поддерживаются.
- Независимая сверка возможна только при наличии отдельного эталонного источника, не того же файла, на котором строилась модель.
